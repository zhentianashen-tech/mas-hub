## Root Cause (Corrected)

### Primary: OpenClaw JSON Output Format Change

**This was the actual killer.** OpenClaw changed the `--json` output format for `openclaw agent` at some point, but the MAS CLI parser (`extract_structured_response()` in `bin/mas`) was never updated.

| Field | Old Format (expected by MAS) | New Format (actual) |
|-------|------------------------------|---------------------|
| Wrapper | `{"status":"ok","result":{...}}` | `{"payloads":[...],"meta":{...}}` |
| Status | `data.status == "ok"` | *(no status field)* |
| Payloads | `data.result.payloads` | `data.payloads` |
| Meta | `data.result.meta.agentMeta` | `data.meta.agentMeta` |

**Effect:** Every agent call returned data successfully, but the parser saw `status=None` and rejected it as unparseable.

**Error in logs:**
```
stage=lead_parse_fail agent=lynch parse_detail={"_error": true, "_stage": "agent_status", "_msg": "Agent returned status=None", "_detail": ""}
```

### Secondary: Stale Session Lock Files

Alonzo's session had a stale `.lock` file from a previous crashed session (pid=51905, no longer running), causing all model fallbacks to fail with lock timeouts.

### Tertiary: `feishu_bitable` in Tools Allowlist

The tool allowlist referenced `feishu_bitable` which doesn't exist as a tool. This generated warnings but was **not the primary cause of failure** — just noise in the logs that initially misdirected diagnosis.

### Cleanup: Feishu Removed Entirely

Alan confirmed he doesn't use Feishu. All Feishu references removed from `openclaw.json`:
- `tools.allow`: removed `feishu_doc`, `feishu_wiki`, `feishu_drive`, `feishu_chat`
- `bindings`: removed feishu channel binding
- `channels.feishu`: removed entire config block
- `plugins.entries.feishu` and `plugins.installs.feishu`: removed

## Lessons Learned

### 1. Test After OpenClaw Updates
OpenClaw can change its CLI output format between versions. After any OpenClaw update, run:
```bash
# Verify output format
openclaw agent --agent lynch --message "PONG" --json --timeout 30 | python3 -m json.tool | head -5
```
Check that the MAS parser can handle whatever comes back.

### 2. Warnings ≠ Root Cause
The `feishu_bitable` and `apply_patch`/`web_search` warnings were red herrings. They generated noisy stderr but were not fatal. The actual failure was silent: a valid JSON response being rejected by an outdated parser.

### 3. The Kimi Code Maintenance Wrapper Needs Testing
First production use revealed three bugs:
- Missing `DIM` and `BOLD` shell variables
- Non-existent `--file` flag for Kimi Code CLI
- Needs to be added to PATH

These are fixed but the wrapper should be tested end-to-end before relying on it.

### 4. Lock File Cleanup Should Be Automated
Stale `.lock` files from crashed sessions can cascade into total agent failure. Add to daily maintenance:
```bash
find ~/.openclaw/agents -name "*.lock" -mmin +60 -delete
```
